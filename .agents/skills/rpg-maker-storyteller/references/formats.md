# 台詞データの形式（2026-10-12時点）

リポジトリの現物で確かめた形式。新しく足すときも、この形に合わせる。現物が変わっていたら現物に合わせる。

## A. 物語の場面（話し手が入れ替わる会話）

見本：`data/first_region_gado_scenes.json`

```json
{
  "id": "場面のID（英小文字と_）",
  "flag": "見終えたことを記録するフラグ名",
  "title": "画面に出る場面名",
  "party": ["pc_01", "pc_02", "pc_03"],
  "form": "human",
  "lines": [
    {"speaker": "状況", "text": "地の文。1〜2行にとどめる。", "action": ""},
    {"speaker": "カイナ", "text": "台詞。", "action": ""}
  ]
}
```

- `party`：場面にいる仲間。`pc_01` カイナ、`pc_02` リオネ、`pc_03` ハルド、`pc_04` スイナ
- `form`：話し相手の姿。ガドでは `human`（人の姿）と `shell`（甲殻の魔物の姿）を使っている
- `speaker`：人物名。地の文は `状況`
- `action`：今のコードが知っている値は、ガドの場面の `leave_tool`（道具をそっと置く）と `tend_wound`（許された傷を手当てする）だけ。ほかは空文字 `""` にする。新しい動きが要るときは、確認票の「組み込みに必要なもの」に書く
- 同じ場面を、先に別の出来事を済ませた場合の版として持つときは、ガドの `encounter` と `encounter_after` のように別の `id` を作る
- 注意：今のコードが読み込む場面ファイルは `data/first_region_gado_scenes.json` だけ（`scripts/world/first_region_story.gd`）。新しい場面ファイルを足すには、読み込みのコードが要る。確認票に書く

## B. 住人の一言（話しかけると出る台詞）

見本：`world/region2_village.json` の `events`

```json
{
  "id": "oasis_water_keeper",
  "kind": "npc",
  "sprite": "npc_oasis_water_keeper",
  "label": "泉の番人",
  "cell": [29, 12],
  "reach": 1,
  "text": ["泉のそばでは、足元に気をつけてください。"]
}
```

- 台詞を書くときに変えるのは `text`（ページごとの配列）だけ。`id`・`sprite`・`cell` などは変えない。新しい住人の場合、`id` と `label` は仮にして確認票に書く（名前は要決定）
- `label` が画面の話し手の表示になる
- 進行に応じて台詞を変える一般の仕組みはまだない。今は `after_text` を、特定の条件（山道が開いた後、ハルドの用事が済んだ後など）でだけ使っている（`scripts/game/game_session.gd`）。進行段階ごとの差分を書くときは、段階ごとの `text` を分けて出し、確認票の「組み込みに必要なもの」に「進行段階で台詞を切り替える仕組み」と書く
