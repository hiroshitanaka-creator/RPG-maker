# 長編の実装・検査記録

2026年9月21日。対象は既存の長編制作の残件。物語の解答はこの記録に記さない。具体的な人物・台詞・装置の事情は設計者の提案として実装した。依頼者が定めた約60時間の目標を変更しない。

## 本番へ接続した内容

| 項目 | 実装データ |
|---|---:|
| 連作・冒険 | 20連作・80話。未制作だった12連作48話を執筆 |
| 再訪する内部区画・訪問場面 | 80区画・320場面 |
| 長編内の戦闘・意思決定 | 480戦・80件。敵のHPや移動速度は変更しない |
| 現地の観察・装置 | 160観察・80装置。順序、視点、配分、実際の地形に基づく経路比較の4種類 |
| 装着を使う判断 | 堅守を装着した生存者がMPを払い近道を残すか、MPを温存して手順だけで進むかを毎話選ぶ |
| 設置と回収 | 長編46件。既存8件を含め手帳54件。依存ID、既読前後の公開境界を保持 |
| 過去の場面 | 20場面。現在の登場人物を見てから、一続きの本文として提示 |
| 本文の文字数 | 85,627文字。既存部分も含む長編本編台詞の延べ数。選択結果・観察は別。読了時間の推計には使わない |

全80話を通常の新規開始で有効にした。既存6章・20職・30敵、旧25区画を維持する。独立した連作の選択順を選べる。旧セーブへ長編を強制挿入しない。

装置は両方の観察を読んでから操作する。誤答ではMP・報酬・進行を変えない。未習得、未装着、MP不足、戦闘不能の支援を拒否し、手順による解法を残す。観察・操作・支援・物語の選択は保存し、再訪時の通行判定に反映する。未知のフラグや未観察での完了旗を保存から受け入れない。

## 検証と受入の対応

すべて `godot --headless --path . --script res://tools/<検査>.gd` で実行する。実描画の検査だけは `--headless` を外し `-- --native` を付ける。

| 条件 | 検査 | 現在の証拠 |
|---|---|---|
| 全20連作80話・80区画が存在し、本番で有効、定義エラー0 | check_long_content | long-content-current.json |
| 全区画で通行可能、閉鎖地形を到達可能と誤認しない | check_long_geometry | long-geometry-current.json |
| 46IDの設置・回収・依存が有効、先の解答公開0 | check_long_clues | long-clues-current.json |
| 過去20場面の提示順と本文の分断0 | check_long_past | ローカルログ・CI |
| 全80装置で不足条件を拒否し、手順による進行が成立 | check_long_device_boundaries | long-device-boundaries.json |
| 3人・4人、80話、支援ありなしの320操作と640表示が成立 | check_long_device_ui | long-device-ui-headless.json |
| 実描画で4種×2編成×2操作の16操作、32表示が成立 | check_long_device_ui --native | long-device-ui-native.json |
| 全80話の3人・4人で全滅後に観察・判断・報酬を保持し、帰還再開できる | check_long_recovery | long-recovery.json。HP1の局所入力から実戦闘で全滅させる |
| 全20連作で3人・4人×両選択、320話分・1,920戦が成立 | check_long_integration -- --arc=ID | CIのlong-branches 4ジョブ。対象章の入口を置く部分検査と明記 |
| 新規開始から80話・80装置を経て結末へ到達し、54件の手帳が回収済み | check_long_full -- --party=3/4、逆順は--reverseを追加 | 4経路をCIで検査。完了フラグ・能力値・勝敗の注入なし。修練後の担当職への復帰と、連戦の合間の補給を含む |
| 全進行地点の保存でキー・型・値・配列順序不一致0、復元先で次の進行を継続 | check_long_full | long-full-*.json。広域へ出て戻る状態も含む |
| 合成72,000件の履歴を往復して不一致0、合成時間を人間受入へ混入しない | check_long_capacity、check_long_record | long-record-capacity.json。人間の60時間実測ではない |
| GodotとPythonの実行版IDが一致し、worldの変更も検出 | check_v1_finish、python tools/check_build_identity.py | nonhuman-v1-checks.json・実行ログ |

`docs/verification/`のJSONには実行版IDと結果を保存する。通し検査は検査コード自体のハッシュも保存する。CIのログで診断エラー・警告・FAILを拒否する。結果ファイルの存在だけで合格にはしない。

保存容量の暫定予算は通常の完走記録1MiB未満、保存・復元各2秒未満。高頻度操作を想定した毎分20件・60時間相当の合成負荷では16MiB以下、保存・復元各5秒以下。後者は通常の完走経路より大きい負荷を試すために分けた。履歴を削除して収めず、JSONの整形用空白だけを省いた。閾値は提案値であり承認済みとはしない。

## 検査中に修正した点

- 自動入力が複数戦の最初の1戦だけで進もうとする不備を修正した。実際に全戦勝ってから進める。
- 自動入力の毎戦の不要な装着解除・再装着をやめ、必要な構成変更だけを行うようにした。
- 初回の3人通しは70話後に敗北した。失敗記録を保持し、実セーブから原因を再現した。修練後の担当職への復帰、通常の帰還・補給、連戦途中の補給を入力方針に追加した。固定入力のAC-01・AC-02、敵の能力値、勝利の期待値は変更していない。途中再開の診断を新規開始の完走証拠にはしない。
- 保存対象に広域状態を追加した際、既存の往復保存検査に広域の実例がなかった。実際に広域を開く・閉じる二状態を追加し、列挙範囲の検査を維持した。
- 装置で支援担当を選んだ後、装着画面でその技を外した場合、表示と内部の担当選択が一致するよう修正した。
- 保存対象一覧に広域状態を明記し、実行版IDにもworldのグラフ・地形・内部データを加えた。
- 複数敵を扱う局所検査では、公開HPが低い敵を先に狙って数を減らす方針を使う。固定勝率の検査方針は変えず、分岐接続の検査と分離した。
- 人物歩行の検査が実時計の移動間隔より早く入力する場合があった。ゲーム側の150ms制限を変えず、既存の実時計待機関数で160ms待つようにした。
- 旧経路の画面操作検査は旧保存の経路と明記した。長編を外した短い通しを、新規開始の長編完走として扱わない。

## 人間の入力が必要な範囲

初見の実時間、反復感、観察から気づけるか、探索・報酬・難易度・構成選択の満足度は `PLAYTEST_QUEUE.md` に残す。目標60時間の設計予算3,600分を実測済みとはしない。本人の初見を消費する試遊を作業の条件にしない。

別件として、旧企画の職別行動回数と凍結JPマスターの衝突は既存の `ESCALATION-R02-R04-JOB-ACTIONS.md` に残る。保護テストを変えずに両方を同時成立させることはできないため、今回の長編実装の合格で解決済みとはしない。
