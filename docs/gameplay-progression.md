# 通常プレイでの育成と帰還

2026年9月19日の追加実装。既存の第1章・20職・5種の敵を使用し、新しい章・職業・画像・独自の制作段階は追加していない。

## 問題と変更

以前は物語上の5戦しかなく、途中で転職すると習得JPを補う戦闘機会がなかった。探索中に町へ戻る操作もなく、町の祠で魔物化を解除する選択を使える場面が限られていた。

- 水路の最初の戦闘を終えると「周辺で戦う」が使える。スライムとコウモリを交互に相手にする。
- 地下回廊の最初の戦闘を終えると、同じ操作で硬殻の番兵と残り火の精と戦える。水門のボスは任意戦闘に含めない。
- 任意戦闘でも通常の勝敗・消費・JP・習得・魔物化処理を使う。勝っても物語手順、位置、伏線フラグは進めない。
- 探索中は「町へ帰還」で町に戻り、休息・転職・装着・祠での解除を行える。「探索へ戻る」で元の場所・マスへ戻る。戦闘途中の帰還は拒否する。
- 帰還先と任意戦闘回数をセーブし、読み込み後も探索へ戻れる。従来のセーブに新項目がなくても読み込める。
- 転職候補を選ぶと、確定前のHP・MP・各能力値と技習得までのJPを表示する。比較を見るだけでは現在の状態を変更しない。
- 習得した技は勝利後に通知する。装着画面では対象、消費MP、効果を日本語で表示する。
- 祠での解除は「やめる」と「消去して解除」の確認を挟む。確認を開いた時点と取消時点では、技や侵蝕度を変更しない。既存の解除処理に合わせ、人間職でも習得できる共有技は残ることを表示する。
- セーブの探索位置が欠落・未知の地名・通行不能座標の場合は読み込みを拒否し、現在の状態を保持する。

任意戦闘の解放時期、敵の交互出現、町への帰還費用なしという扱いは調整案。任意戦闘の反復で5〜6時間の目標尺を満たしたとは扱わない。

## 検証

保護された`test/`、`tools/smoke_chapter1.gd`、スキーマ、契約、`project.godot`は変更していない。追加の操作検査は`tools/check_progression_paths.gd`に置いた。

実装前にこの追加検査を実行し、終了コード1を確認した。探索位置の不正な読み込み、帰還・任意戦闘・解除確認の未実装など13件の失敗を観測した。

実装後、4人編成の実描画と3人編成のheadless操作で`PROGRESSION_PASS`を確認した。検査は次を実行する。

1. 新規開始し、通常の移動・会話・戦闘で水路の最初の勝利へ進む。
2. 町へ帰還してセーブし、別インスタンスへロードする。元の探索位置・物語手順へ戻れることを確認する。
3. 魔物職へ転職し、任意戦闘を繰り返してJPを獲得、マスターして魔物化する。
4. 習得した酸液を装着し、通常の戦闘コマンドから使用する。他の仲間には防御を選び、技が実行されMPが消費されることを確認する。
5. 町で解除確認を開き、取消では状態を保持し、確定では魔物化と専用技が消えることを確認する。
6. 20職の比較が状態を変えず、実際の転職後の能力値と一致すること、従来セーブを保持して読めることも確認する。

初回の技使用検査では、他の仲間が先に敵を倒し、酸液が不発になった。期待値やアサートは変えず、他の仲間に防御を指示して技を実行できる入力に修正した。未実行の技がMPを消費しない既存の戦闘仕様は維持している。

```powershell
godot --headless --path . --script res://tools/check_progression_paths.gd
godot --headless --path . --script res://tools/check_progression_paths.gd -- --three-member-party
python tools/run_locked_checks.py
python tools/check_frozen_files.py
python tools/validate_assets.py --strict
```

CIでも既存8verifyの後に、3人・4人の追加操作検査を実行する。実画面は`docs/verification/screens/progression_*.png`、実描画のログは`docs/verification/progression-native.log`に保存した。人間による操作性・難易度・5〜6時間の評価は未実施。
