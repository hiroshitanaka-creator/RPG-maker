# 通常CIと旧本編の手動検査の分離

2026年9月27日、依頼者の指示で実施。スプリント3の前に旧本編の検査を通常CIから外し、同じ検査を手動ワークフローに保持する。

## 変更前の検査と移動先

| 検査群 | 扱い | 理由 |
| --- | --- | --- |
| 最悪ケースの全章通し、80話の4条件、20連作の4グループ | 手動 | 旧章・旧長編の全体検査。既存の手動定義と一致していたため通常CIの重複だけを除く |
| 旧章の再訪2順・結末・保存全変数 | 手動 legacy-story | 従来25分ジョブを圧迫した通し操作。コマンド、各600秒制限、成功件数を保持 |

| 80話＋49拠点の機構配分、長編検査再開記録、旧世界メニューと49拠点の通し | 手動 legacy-preplay | 旧本編の構造・操作・保存に依存 |

## 守った条件

- `.scope-lock/**`、`test/**`、保護された検査、検査スクリプト本体は変更しない。
- 旧本編検査は削除せず、`workflow_dispatch` だけの `.github/workflows/legacy-campaign.yml` へ移す。
- 通常CIは3ジョブ。手動CIは6定義、行列を展開すると12ジョブ。
- 旧本編の通し保存と旧保存・UIを別ジョブにする。双方25分。通常Godotも25分のままで、移動した各コマンドのtimeoutは元の値を保持する。
- 通常CIの成果物には、手動へ移した未実行の旧結果を混ぜない。
- 変更前コミットは `13518300ac64954268ff3ee7249662b7313ac859`。76種類の検査・準備コマンド、32種類の成功件数判定、56組の警告検出と対象ログについて、移動後の通常＋手動から欠落0件を確認した。行列ジョブ3定義と凍結verify工程は内容一致。
- 照合記録は `docs/verification/ci-legacy-split.json`。結果を適用するワークフローのSHA-256も記録する。

## 実行方法と時間の確認

通常CIはpush・pull_requestで実行する。手動検査は `gh workflow run legacy-campaign.yml --ref main` で明示実行する。

移動後の通常CI全ジョブと手動CI全ジョブの終了を確認する。通常Godotの所要時間は10分以内を確認目安にし、25分上限を変更して達成したことにしない。実行時間はGitHubのジョブ開始・終了時刻から測る。まだ実行していない結果をPASSと記録しない。

## 版識別の入力

通常CIの最初の実行で、旧検査を移すとGodotの版IDをその環境で再記録する処理もなくなり、過去のWindows作業ツリーの記録とLinuxのチェックアウトのバイト列の差で版識別が失敗した。作業ツリーとコミットの内容はGitでは同じ扱いでも、改行のバイト列が異なる5ファイルを確認した。

新ゲームの画面10項目の検査を先に実行し、その検査がGodotの `BuildIdentity.current()` で実測した値を、既存の `check_build_identity.py` へ入力する。Pythonで比較元の値を計算して渡す方法は使わない。比較・変更検出・旧記録拒否のアサーションは一切変えない。入力の受け渡し中だけ一時的に記録ファイルを使い、履歴資料の元のバイト列は `finally` で必ず戻す。旧本編の検査を通常CIへ戻したり、実行していない旧検査をPASSと記録したりはしない。
