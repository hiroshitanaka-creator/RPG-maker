# 戦闘・職業編成の実装範囲

> この文書は凍結入力を受領する前の作業記録。現在の要件は `.scope-lock/spec.lock.json` のR-01〜R-08であり、人間12職・モンスター8職、3〜4人パーティである。以下の5人間職や制作段階の記述を、現在のスコープや新しいマイルストーンとして扱わない。

## 確定条件と今回の到達点

AGENTS.mdの固定事項に従い、Godot 4.7.2-stable、GDScript、2D、内部解像度512×288を使用する。企画書第9節の未選定という原文は履歴として保持する。エンジンを置換する提案や実装は行わない。

制作順の第1段階「戦闘とダメージ計算」と、第2段階のうち職業・装着を操作して比較できる部分を作る。4人は開始時点でそろっている。画面は戦闘検証用であり、本編の町・ダンジョン・物語・成長を置き換えるものではない。

画像素材が不足しているため、この段階はGodotの標準コントロールによる編成・戦闘画面とする。代替キャラクター画像や背景画像は生成しない。提供画像15点は取り込み前の原本として保持する。

## 提案として実装する戦闘規則

以下の式・数値・技名・模擬敵は調整用の提案であり、依頼者が確定した最終バランスではない。

- コマンドは攻撃、防御、装着アビリティ、回復薬。生存している仲間全員の行動を選び、確定後に1ターンを解決する。
- 防御はそのターンの攻撃解決前に有効化する。他の行動は優先度、素早さ、固定IDの順で処理し、同速時も順序を再現できるようにする。
- 物理の基礎ダメージは `max(1, 攻撃×2−防御)`。技の倍率を掛けて切り上げる。
- 魔法の基礎ダメージは `max(1, 技威力＋魔力×2−魔法防御)`。弱点属性なら1.5倍。
- 通常防御はダメージを0.5倍、堅守は0.25倍とし、最後に切り上げる。乱数によるダメージの増減と会心はこの段階では未実装。
- 治癒量は `技威力＋魔力×2`。HP・MPは上限を越えず、HPは0未満にならない。蘇生は戦闘不能の味方を最大HPの25%で復帰させる。
- MPと回復薬は行動が成立したときだけ消費する。行動前に倒れた者は行動しない。単体攻撃の対象が先に倒れた場合は生存する敵へ変更する。回復・蘇生は対象の状態が合わなくなったら不発にし、資源を消費しない。
- 回復薬は戦闘開始時3個、回復量50。盗むは対象1体から1回だけ回復薬を得る検証用の効果とする。実ゲームの所持品・盗み確率・獲得物・実績の永続化は未実装。
- 検証画面では人間職5種の技を全員が習得済みとして扱い、開始時の2枠へ自由に装着できる。転職しても装着内容は維持する。本編の習得条件・JP成長を実装済みとは扱わない。
- 中盤の3枠、魔物化による+1枠、最大4枠という容量計算を用意する。魔物化を発生させる条件は未決定のため、本画面からその状態へ進行させない。

## 所有する状態と呼び出し方

`BattleState` がHP・MP・行動予約・戦闘結果を所有する。画面は `queue_action()` で予約し、`resolve_round()` の戦闘記録を表示する。JSONの読み込みと検証は `BattleCatalog` が担当し、装着可能性は `Loadout` にまとめる。

| ファイル群 | 担当 |
|---|---|
| `data/battle_lab.json` | 調整用の5人間職・10技・5模擬敵・対戦編成。全12職の一覧と未実装状態も保持する。 |
| `scripts/combat/` | キャラクター、行動、ダメージ式、装着、戦闘状態。画面ノードを参照しない。 |
| `scripts/ui/battle_lab.gd` | 編成、対象選択、戦闘記録、勝敗、再戦。 |
| `tests/` | 数値計算だけでなく、死亡・資源不足・対象変化・二重行動・勝敗・画面操作の検証。 |
| `tools/verify_godot.py` | 固定版の確認、インポート、戦闘テスト、画面テストを実行し、タイムアウト・非0終了・エラーログを失敗として扱う。 |

画面が戦闘値と進行を直接変更する案と、独立した戦闘状態を画面から呼ぶ案を比較し、後者を採用する。前者は画面を作りやすいが、戦闘不能者の扱いや資源消費を画面操作なしで検査しにくい。別言語で計算モデルを作る案は、GDScriptとの規則の二重管理を招くため採用しない。
