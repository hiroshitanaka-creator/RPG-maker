# 人間の試遊と5〜6時間の実測

人間による試遊は未実施。現在の自動検査や画像の目視を、人間が新規開始から結末まで遊んだ結果とは扱わない。

## 起動と記録

リポジトリ直下のPowerShellで実行する。

```powershell
.\tools\launch_playtest.ps1
```

ゲーム画面を開いた後、PowerShellを保持する必要はない。タイトルで新しく始める。4人・3人のどちらで遊んだかを自由記述にも残す。途中からの古い保存では、追加区画を含む新規プレイの所要時間は確かめられない。

探索中の「記録」、またはメニューの「試遊の記録と評価」を開く。章の区切りや迷った場面で次を入力し、「回答を記録」を押す。

| 項目 | 1 | 5 | 自由記述に残す具体例 |
|---|---|---|---|
| 探索の分かりやすさ | 分かりにくい | 分かりやすい | 場所、迷った理由、説明を読んでも分からなかった条件 |
| 報酬の満足度 | 足りない | 十分 | 欲しかったもの、薬を使った場面、報酬のために寄り道したか |
| 難易度 | 易しい | 難しい | 敵の組み合わせ、全滅・帰還・構成変更の理由 |

回答はセーブに含まれる。「JSONへ保存」で試遊記録を別ファイルへ書き出せる。ゲーム終了時も、記録区分を指定した試遊の最新レポートを自動で書き出す。進行の保存は探索中の「セーブ」で行う。再スタートする前にもJSONを保存して、前の試行を残す。

Windowsの保存場所は通常、`%APPDATA%\Godot\app_userdata\RPG-maker\`。

- `save_v1.json`: ゲーム進行と計測・回答。
- `battle_checkpoint_v1.json`: 直近の戦闘開始前の進行と計測。手動セーブとは別。
- `playtest-report.json`: 「JSONへ保存」で書いた記録。
- `playtest-human-latest.json`: 人間の試遊として記録した終了時の最新記録。
- `playtest-automated-latest.json`: 自動操作の記録。人間の試遊へ合算しない。

全滅時は「戦闘前へ戻る」で再挑戦できる。HP・MP・薬・侵蝕などの進行は戦闘前へ戻すが、全滅と経過時間は保持する。再起動後はタイトルの「自動保存した戦闘前から再開」を使う。自動保存は戦闘開始前の1件なので、勝利後の移動・会話・課題の区切りでは手動セーブも行う。[復帰の詳細](battle-recovery-v1.md)を参照する。

## 時間の定義

`Time.get_ticks_msec()`の差分を記録する。移動速度や待機時間を変更して尺を作る処理は入れていない。

| JSONキー | 意味 |
|---|---|
| `elapsed_ms` | 起動中の記録時間。保存を読み込むと累積値から再開し、終了中の時間を足さない。 |
| `active_ms` | ゲーム画面が前面で、操作から60秒以内の時間。 |
| `idle_ms` | ゲーム画面が前面だが60秒を超えて操作がない時間。文章を読んでいる可能性もあり、離席とは断定しない。 |
| `pause_ms` | メニュー・評価画面・非アクティブ状態などの時間。 |
| `foreground_play_ms` | `active_ms + idle_ms`。読む時間も含むプレイ中の時間。 |
| `chapters` | 章ごとの経過時間と操作中時間。経過時間には休止も含む。 |
| `events` | 戦闘相手・勝敗・ターン・JP・残HP/MP・侵蝕、転職、装着、課題への回答。 |

結末への到達後は計測を止める。長い無操作がある記録は、読書・思考・離席のどれだったかを本人に確認する。休憩を含めた5時間を、そのまま内容量の5時間とは扱わない。

## 集計

```powershell
. .\tools\prepare_scope_env.ps1
python tools\summarize_playtest.py "$env:APPDATA\Godot\app_userdata\RPG-maker\playtest-human-latest.json"
```

集計は元JSONの時間・勝敗・回答を表示する。人間の自己申告、新規内容版、5点検の完了、結末到達、300〜360分の範囲をそれぞれ確認する。生成時の内容データのSHA-256を残すため、違う版の結果も区別できる。

`duration_candidate`は時間帯の候補判定であり、受入完了ではない。`status`は人間の記録と回答が揃っても`REQUIRES_HUMAN_REVIEW`で止まる。自動操作、混在した記録、未完走、版の不一致、回答なしは`NOT_ACCEPTED`。自己申告だけで本人性を証明したとはせず、`human_identity_verified`はfalseを保持する。

実際の記録を受け取り、探索・報酬・難易度の回答、失敗した戦闘、長い無操作を確認してから、尺とバランスの調整が必要か判断する。短すぎる場合は内容を追加し、長すぎる場合は移動・戦闘・説明のどこに時間がかかったかを確認する。未提出の回答や所要時間を作って埋めない。
