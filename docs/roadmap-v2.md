1. 役割
役割	やること
依頼者	スプリントの開始を指示する。確認用画像を見て採否を決める。未決事項（第6章）を決める。承認画面で内容を確かめて承認・拒否する
Codex	各スプリントの作業計画を自分で立て、実装・検査・コミット・pushを行う。判断が必要な点は、選択肢と推奨を付けて依頼者に聞く
2. 1スプリントの進め方
docs/roadmap-v2.md、AGENTS.md、docs/experience-spec-v2.md を読む。
そのスプリントの作業計画（目的、変更するファイル、使う検査、作る確認用画像）を10行以内で報告の冒頭に書き、承認を待たずに作業する。
作業を終えたら、確認用画像・検査結果・CIの結果を報告して止まる。
依頼者が「採用」と返したら完了とする。「直してほしい点」が返ってきたら、その点だけを直して再び報告する。

1スプリントが長い場合は2〜3回に分けてよい。分けた場合も、区切りごとに確認用画像を出して止まる。

3. 共通ルール

次のルールを AGENTS.md の「2026年9月25日の承認済み改訂（世界マップ攻略型）」の節の末尾にも追記すること（スプリント1で行う）。

作業の前後で、未コミットの変更と未pushのコミットを一覧にする。そのスプリントと関係ないコミットはpushしない。
検査を弱める・飛ばす・時間上限を延ばすことで合格させない。実行していない検査を成功と書かない。CIは全ジョブの終了を確認してから結果を書く。
特定のスプリントを確かめるための一時的な検査は、比較の相手を「そのスプリントの最後のコミット」に固定して作る。作業ツリーと比べる形にしない。
保護ファイル（.scope-lock/**、test/**、保護された検査）や契約を変える必要が出たら、止まって依頼者に選択肢を示す。
見た目に関わる作業では、確認用画像を docs/verification/ に保存し、目標の絵（docs/reference/visual-targets/）と並べて比べる。
素材は出所を台帳に記録する。依頼者の原画は1バイトも変えずに保管する。
判断が必要なときは、選択肢を2〜3個と推奨・理由を示す。できないと言う前に、使える手段を試すか、その手段があることを伝える。

## 物語の大筋

2026年9月26日に依頼者が採用した。世界には太陽・月・海・戦い・実りの5柱の神がいる。物語の始まりの時点で神々は黒く染まり、各地に災いをもたらしている。主人公たちは世界を旅して、神を1柱ずつ本来の姿へ取り戻していく。

- 後半の自由順の4か所（塔2つ・ダンジョン2つ）には、黒く染まった神が1柱ずつ待つ。月・海・戦い・実りの4柱を当てる（どの神をどこに置くかは後半を作るときに決める）。
- 倒すと神は本来の姿に戻り、「神の加護」を1つ授ける。進行表の「封印を解く宝」は、この4つの加護である。
- 4つの加護がそろうと、最後の地の封印が解ける。最後の地には太陽の神がいて、物語の結末に関わる（仮）。
- 加護を戦闘で呼び出す仕組み（召喚など）は新しい要素の追加になるため、今は作らない。加護は物語上の鍵として扱う。
- 絵は、依頼者が作画した神々の明るい姿と黒く染まった姿の対を使う。

### 依頼者が作画したその他の人物

- もう一組の冒険者：若い4人は、仲間とは別の冒険者の一行として、各地で出会うライバル、または一時的に同行するゲストとして登場させる。ゲストのときも職業は変えない。戦闘の動作の絵は、会話や事件の場面の演出に使う。
