## 実装計画
Goal：副作用のない台帳と装備変更APIを動かし、後続が同じ判定を再利用できること。
Architecture：定義と個体所有を分離。stateのcopyを計画器で検証・変更し、成功候補と理由を返す。既存GameSessionを呼び出して書換えない。
Tech Stack：Godot 4.7.2-stable、GDScript、JSON。
Spec：docs/design/equipment-foundation-plan.md 3〜5節と本依頼の採用追記。

### 担当ファイル
- equipment_rules.json：規則版1、12職/8魔物職の可否、既存6品の互換参照と採用新8品、仮値ラベル。旧データは変更せず読み取って重複定義の食い違いを検査
- equipment_rules.gd：定義読取り、所有検証、合法判定、装備/転職/能力変更の純粋計画API。ここでゲーム保存を読み書きしない
- check_equipment_rules.gd：固定期待値による正負検査、終了コードと件数/失敗一覧の機械読取結果。期待値を本番関数から生成しない
- 候補書末尾：候補の旧本文を残し、日付・回答・A採用と名称訂正を追記する。歴史的B案を削除しない
- 報告と検証結果：実行SHA/版/コマンド/件数/失敗/未接続を記録

### 外部インターフェース
034の名前を基本にする：
- validate_equipment_state(state: Dictionary) -> Array：空配列なら有効、エラーには対象と理由
- plan_equipment_change(state: Dictionary, actor_id: String, request: Dictionary) -> Dictionary：ok/reason_code/candidate/moves。成功時だけcandidate、入力は成功失敗とも不変
- 合法可否と補正取得のpublic関数は小さく分け、実際の名前・型・stateの必要キーを報告の契約表で固定する
正規化stateはequipment_rules_version、equipment_stock.instances/bag、party/reserve内のequipmentを扱う。既存人物の情報を無駄に複製せず、必要な職/能力を使う。旧stateが来たら勝手に移行しない。
転職解放・不可逆・戦闘中禁止などゲーム全体の入口判定は既存GameSession側の後続責任。今回の純粋装備計画器を、職変更が許可済みである証拠として使わない。この責任分界をAPI契約へ明記。

### 実装の順序と検査
- [ ] 1. 全変更可能パス/固定SHA/既存未コミットを確認し、報告冒頭へ計画を記載
- [ ] 2. まず不足・誤入力・所有不変の失敗する検査を用意し、失敗理由を記録
- [ ] 3. データと所有検証を実装。未知ID、重複所有、孤児、partyとreserveの二重所有、不正枠/版/型を拒否
- [ ] 4. 手動付替え、転職時の自動選択、能力変更に伴う返却の計画器を実装。入力deep copy、他人やreserveから奪わず総数不変
- [ ] 5. 仮値を含む補正集計を実装。同名別個体合算、同一個体の重複拒否。副作用・現在HP/MPの更新なし
- [ ] 6. 以下の全機械検査を指定Godotで実行し、失敗を直す。必要な警告も放置しない
- [ ] 7. 既存素材取込み/R/保護/CI、変更範囲/差分検査、commit/push後の同一SHA全CIを確認して報告

## 機械受入
1. 人間12職×武器5分類、防具3段階、装飾各枠、魔物8職：034表の合法集合と一致。刀は剣分類。重が中軽を使え、中が軽を使える
2. 正規化fixtureの全20×20=400職切替で装備移動の期待を確認。ただし職解放・不可逆判定を省略した実ゲーム成功とは呼ばない
3. 同率従前優先、袋のより強い品選択、負値の術杖も合法実物なら空より選択、候補なしだけ空、他人/reserve不変、同名2個体は別個数
4. 人間→魔物は武器全数/防具を袋、装飾1/2保持/3空。逆は3袋/武器防具自動。人間同士と魔物同士は装飾順保持
5. 二刀流解除で第2武器だけ返却。手動能力装着で勝手に最強へ変更しない。両手持ちと二刀流の同時装着拒否。防具/装飾枠不変
6. 全instanceが袋または全人物の枠のちょうど1箇所。未知ID/重複/孤児/不正型/版/枠/対象人物/仲間所有品指定を拒否し入力不変
7. 同名装飾1/2/3個の仮値合算。未選択の萎縮免疫品/効果を定義しない。人間3枠目は無効
8. 初期カタログの既存6品名/ID/値/効果が旧原本と一致、新5品名と装飾3品名が採用どおり。鉄の小短剣を採用品として登録しない
9. 成功失敗とも入力不変、candidateを後から変更しても元入力と共有参照で変化しない。安定した同点順を複数実行で確認
10. 既存ゲーム接続ゼロ、新規開始/保存/戦闘の動作を変えない。R-01〜08全成功、保護26一致、CI全成功

新検査コマンド：timeout 240 godot --headless --path . --script res://tools/check_equipment_rules.gd
期待：終了0、EQUIPMENT_CORE_PASS、件数明記、失敗0、SCRIPT ERROR/ERROR:/WARNING:/Parse Errorなし。既存時間上限は変更しない。
