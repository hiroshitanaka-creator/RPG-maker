# ワールドマップの構造定義 — Phase 1

状態: 構造の提案をJSONに定義。地形とゲームへの接続は未実装。Phase 2〜4の合格や60時間の内容量達成を示す文書ではない。

## 承認範囲と既存成果物

依頼者の「A方針でPhase 1へ進めてください」に基づく。目標は256×256タイル、3〜4地方、町村10〜12、ダンジョン14〜18、小拠点20〜25、徒歩・船・飛行の3段階、約60時間。Godot 4.7.2-stable、GDScript、内部512×288px、32pxタイルを維持する。

既存8拠点のID・名称・種別と、移動イベント15件から抽出した11種類の有向接続を保持する。重複する往復は一本の双方向edgeで表す。新しい広域の解放条件は提案であり、既存のquest_step・ローカルマップ・再訪イベント・保存処理は変更していない。

従来の「町3・ダンジョン5」は保存する既存拠点の数とする。今回承認された広域目標の上限とはしない。既存25区画と長編用80部屋を別々のワールド拠点に数え直さない。既存6章案、20職、30敵、8回収・2連鎖の削除や、新しい大陸・章・職業の追加は行わない。

正本は `world/map_graph.json`。座標、地形、ローカルの出現位置は入れない。新規名称・推奨レベル・進行順・物語上の役割・移動秒数・解放イベントは提案値。

49拠点・59接続。新規提案は町村8、ダンジョン11、小拠点22。移動段階ごとの所属は徒歩17・船16・飛行16であり、解放直後に到達できる数の検証結果ではない。

町・ダンジョンを結ぶ推奨経路に、任意の小拠点と帰還用の別経路を接続する。船と飛行の準備を行う2小拠点は任意扱いにせず `visit_policy: transport_unlock` とする。既存拠点への帰還経路も残す。全59接続は双方向とし、離れた場所への一方通行による閉じ込めを設計上避ける。

## データの読み方

| 対象 | キー | 意味 |
|---|---|---|
| node | id / name / type | 小文字ASCIIと数字と下線のID、名称、town・dungeon・outpost |
| node | region | 広域地方のID。既存長編のregionとは別の名前空間 |
| node | recommended_level / progression_index | 初訪問の推奨レベルと推奨順。順は1〜49、レベルは暫定1〜45。レベルを実行時の入場制限にはしない |
| node | required_transport | 初訪問に必要な最低移動解放段階。上位解放後も徒歩・船を保持 |
| node | unlock_flags | 全要素がtrueなら解放。空配列は条件なし |
| node | story_role | この場所で何を知る・選ぶ・準備するか。実装済みの台本を意味しない |
| node | origin / legacy_location | existingとproposedを区別。既存拠点だけ元のIDを対応付ける |
| node | visit_policy | recommended・optional・transport_unlock。推薦順と強制訪問を区別 |
| edge | id / from / to | 接続IDと始点・終点 |
| edge | required_transport | その接続を通る移動手段。nodeの最低段階とは役割が異なる |
| edge | expected_travel_seconds | 通常速度で経路だけを移動する想定秒数。戦闘・会話・メニューを除く。実測ではない |
| edge | one_way / unlock_flags | falseなら両方向で同じ条件と想定秒数。両端nodeの条件も満たす必要がある |
| edge | roles | 推奨経路・寄り道・準備・既存接続・帰還経路の用途。複数用途を持てる |

フラグは3個。初期値false、永続、非消費とし、解除後にfalseへ戻す遷移を作らない。各フラグの設定場所・契機・前提をJSONに記述した。前提は通路整備→船→飛行の順。取得を戦闘の敗北、消費品の残量、特定職や魔物化の強制に依存させない提案とする。

船は接続の端点で乗降、飛行は端点で離着陸できる案。燃料切れや乗り物の置き去りを導入しない。地形上の船着場や着陸範囲はPhase 3で対応付ける。

`progression_index`は初訪問の推奨順であり、帰還時の逆順移動を禁じない。Phase 2ではこの順に並べた推奨レベルの非減少を検査する。全edgeで厳密な増加を要求すると再訪と双方向移動が両立しないため、帰還辺を進行順の違反と解釈しない。

`completion_node`は構造検証用の終点。既存の結末をそこへ移す決定ではない。既存の終盤へ戻す接続と台本の対応はゲームへの接続時に検証する。

## Phase 1の受入条件と検査

godot --headlessで実行し、必須項目の欠落、ID重複、未定義参照、既存8拠点・11接続の欠落、座標・地形項目の混入がそれぞれ0件であり、拠点数と地方数が指定範囲内、移動手段が3段階であること。

```powershell
godot --headless --path . --script res://tools/check_map_graph_definition.gd
```

検査器は、グラフ作成前に「world/map_graph.json が存在しない」で終了コード1となることを確認した。ローカル環境で標準ログの保存先が書込み制限を受ける場合、`--log-file .tools/map-graph-definition.log`を追加してログだけをリポジトリ内の無視対象へ出力する。

この検査はPhase 1専用。到達性、フラグの循環、全状態の詰み、移動解放後の到達数、実際の地形経路・移動時間は検査しない。それらを合格と表示しない。
