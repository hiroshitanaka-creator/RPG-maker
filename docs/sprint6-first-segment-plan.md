## 目的と区切り

**推奨：第1地方の港から船で第2地方へ渡り、最初の港町で補給・保存・帰還できるところまで。** 海で移動できる範囲が広がったことを、実画面で確認できる区切りにする。

仕様書の節目6全体は「第2地方の島々 → モンスター職の解放 → 奥地」。最初の港町を採用した後、島の探索と解放の場面を次の区切りにする。解放の出来事・人物・場所は別途提案し、未決の物語を先に実装しない。続いて節目7の鍵、節目8の第3地方沿岸と上級職、節目9の城と飛行手段を扱う。この計画でスプリント6全体を完了扱いにはしない。

## 配置を決める順番

1. まず、この区切りの範囲・仮の呼び方・原画方針を依頼者に選んでもらう。
2. 指定された港町の目標画像と、次の3つの配置案を並べた画像を作り、実装前に選んでもらう。下記は比較画像の制作方針であり、まだ採用済みの配置ではない。
   - A：入り江を囲む港町。桟橋→港務所→店→宿が近い。**推奨**。船で着いて補給する流れを見通しやすい。
   - B：海沿いに細長い港町。海岸の通りに施設を並べる。港らしい眺めが続くが、施設間の移動が長くなる。
   - C：丘と港の二段の町。下に桟橋と店、上に宿と祠。高低差が分かるが、斜面・階段・遮蔽物の確認箇所が増える。
3. 配置案には各施設の入口、海と陸、住人、通行経路、船の乗降位置を載せる。目標の絵との差を依頼者が判断できる状態で止まる。
4. 選ばれた配置と原画に合わせて実装する。完成後は以下の確認画像・検査結果を報告して再び止まる。

町の配置図・原画比較画像は今回まだ制作しない。目標画像が未指定のまま、配置を確定しないためである。

## 将来の変更対象と確認内容

変更候補は `world/map_graph.json` の既存拠点への割当、`world/first_region*.json` の地域・船・帰還の接続、`scripts/world/first_region*.gd` と `scripts/game/game_session.gd` の対応箇所、室内変換用の `tools/`、`assets/interiors/`・台帳・出所記録。新しい地方のデータをどのファイルへ分けるかは実装計画で確定し、既存のIDと保存の解釈を保つ。今回これらは編集しない。

現在の `FirstRegion.entrance_landing` は第1地方の入口キーと扉の配列を探す。第2地方の新しい接続が自動的に対象になると決めつけず、各部屋の入口の着地が解決できることを実際に確認する。

実装時の機械検査案：

- 通常の船操作で第1地方→第2地方→第1地方を往復できる。海以外に船が入らない。乗降直後の向きと再入場防止を維持する。
- 全施設へ歩いて到達し、住人と会話・宿泊・既存の道具／武器購入ができる。町では戦闘しない。
- 未訪問の町は帰還先に出ず、訪問後に登録される。MP2、使用者条件、乗り物の移動、保存・読込後の一致を確認する。
- 全室の通行地図と実ゲームの通行判定が一致する。入口・扉の前・会話位置に到達できる。
- 旧保存の位置が壁・家具・住人・部屋外なら同じ部屋の入口前へ戻る。歩ける位置は維持する。置き直し後の再保存・再読込で再度移動しない。存在しない部屋や壊れた保存の拒否条件を維持する。
- `check_saved_position_relocation.gd` を含む既存検査、素材検査、凍結照合、R-01〜R-08、通常CI全ジョブを確認する。新規検査・既存検査の更新が必要なら、具体的な差分を示して承認を受ける。今回の計画採用を検査変更の承認とは扱わない。

確認画像案：航路全体、船で到着、町全景と目標画像、室内6部屋と通行地図、海と岸の戦闘、帰還先選択と帰還後、以前の保存の置き直し前後。見た目の採否は機械検査と分ける。
