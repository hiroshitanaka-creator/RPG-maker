# 広域地形・拠点内部・ゲーム接続

> 2026年9月25日：ゲームの形は [世界マップ攻略型の体験仕様 v2](experience-spec-v2.md) に改訂された。本書のうち、進行・拠点・移動・転移の記述が改訂後の仕様と食い違う場合は、改訂後の仕様を優先する。

依頼されたPhase 3・Phase 4と、その後の拠点内部・ゲーム接続を扱う。Godot 4.7.2-stable、GDScript、512×288の内部解像度、32pxタイルを維持する。

新規の地名・依頼台詞・報酬配分は設計者の提案として実装した。依頼者が確定した設定とは区別する。

## 遊ぶ入口

通常の町にいる状態でメニューを開き、「世界地図へ」を選ぶ。新規開始直後の町からも利用できる。

- 広域では矢印／WASDで移動する。地図クリックや「全図」の行き先選択でも現在の移動手段で進める。
- 拠点入口の上で「調べる」と内部へ入る。内部では記録を読み、魔物を退け、相談に答える。
- ダンジョンの「奥へ」はその区画の観察・戦闘後に進める。左下の出口から前の区画や広域へ戻れる。
- 船は船着場の青い点で切り替える。飛行も拠点入口で切り替える。未解放の移動手段や入場は拒否する。
- 船・飛行の解放は既存のグラフで定めた拠点の依頼を完了して得る。報酬と解放は保存される。
- 出発した町へ戻ると「本編へ」で元の冒険へ戻れる。広域の依頼記録は残る。

既存の町・ダンジョン・本編の回収を保持し、広域探索は同じパーティ・職業・装着・HP／MP・薬・JPで遊ぶ。本編の現在地と章進行を残したまま探索し、出発した町へ戻る方式。既存の章間移動をすべて広域歩行へ置き換えたものではない。

`world/map_graph.json`に座標を追加せず、`world/terrain.json`に座標・地形・船着場を保存する。海・水路、草地、森、山、道、橋、入口を区別する。タイル画像は既存の素材を使用する。

`tools/build_world_terrain.py`は同じグラフのPhase 2合格記録とハッシュを確認してから生成する。seedは20260920。拠点の想定移動秒数を変更せず、配置制約の内側に入る座標を探索し、徒歩の道と船の水路を生成する。配置制約を満たせない場合は失敗し、速度低下で埋め合わせない。

徒歩・船・飛行の移動間隔は、既存の徒歩と同じ1セル150ms。移動処理は `WorldMovement` を本番画面と検査で共用する。方向に合わせて歩行・船の向きを変え、停止時は静止コマへ戻る。

`world/interiors.json`は `tools/build_world_interiors.py` の原稿から作成する。新規11ダンジョンは各3区画、町村・小拠点は観察2箇所と選択・報酬を持つ。町村・小拠点には休息場所もある。既存8拠点の内部地形は `ChapterOne` の通行判定を参照し、元データを書き換えない。

## Phase 4の判定範囲

`tools/check_world_terrain.gd`は、AStarGrid2Dの四方向経路探索で、各edgeが指定する移動手段で通れる最短経路を求める。描画用の道を眺めて到達扱いにはしない。

本番の移動処理へ経路を渡し、60Hzのdeltaで到着まで実行する検査と、加速せず単調増加時計で壁時計時間を測る検査を分けた。戦闘・会話・メニューは想定移動秒数に含まれない。実時間検査もheadlessでの移動処理が対象で、人間による操作時間の測定ではない。

| 条件 | 結果 |
|---|---|
| 全edgeが通行可能 | 往路61／61、復路61／61 |
| 移動時間が想定の±50%以内 | ゲーム内時間と、加速なしの61経路実測で検査。各値は結果JSONに記録 |
| 地形変化も拠点もない区間が20秒未満 | 往路最大13.65秒、復路最大16.2秒 |
| 到達不能な陸地が5%未満 | 1,540／49,885タイル、約3.09% |
| 入口を持たない孤立した陸地 | 0タイル |

地形変化は、画面上で見える現在地周辺5×5セルの地形種別集合の変化で測る。座標が変わっただけで変化扱いにしない。拠点セルでも区間を区切る。この基準と全経路の最長区間を結果に保存する。

陸地の検査は、到達確認済みの入口から徒歩の通行規則で探索する。飛行で上を通れるだけの山を利用可能として数えない。山を含め、入口から徒歩で入れない陸地を保守的に到達不能側へ含める。

実時間の結果は `docs/verification/world-terrain-realtime.json`。測定したグラフ・地形・移動コード・通行コードのハッシュを保存し、`tools/check_world_realtime_record.py`で現在の入力との一致と全61件の秒数・到着位置を照合する。途中結果はRUNNINGで保存し、全件終了前にPASSにしない。接続状態の表示を更新する前の実測は `world-terrain-realtime-phase3.json` に履歴として残した。

## ゲームへの接続と保存

`GameSession`に広域探索の開始・終了、移動、乗り換え、内部の観察・選択・戦闘を接続した。観察・戦闘を終える前の進行、報酬の二重受取、未習得の移動手段、不正な位置の復元を拒否する。戦闘のJP・習得・魔物化は既存処理を使用する。

保存対象は `overworld` 内のactive、origin、layer、cell、world_cell、transport、node、room、flags、seen、cleared、choices、visited。旧保存にこの項目がない場合も読み込める。UI上の自動移動は保存時に止め、実際に到着したセルを保存する。

戦闘前は既存の自動保存へ広域・内部状態も含める。全滅後に復帰すると、元の内部位置・編成・薬・進行を復元する。広域戦闘の勝利を旧本編のイベント完了と取り違えない。

| 接続検査 | 結果 |
|---|---|
| 初期4人で全拠点を巡る | 49拠点・22戦・72保存往復 |
| 初期3人で全拠点を巡る | 49拠点・22戦・72保存往復 |
| 各通し検査の通常移動 | 隣接セルAPIで9,194セル。所要時間測定とは別 |
| 全フラグ×拠点の読込境界 | 392件。受理224・拒否168、独立したPhase 2の判定と一致 |
| 不正な型・位置・進行の読込 | 8ケース拒否 |
| 前提フラグ欠落からの実地形上の帰還 | 4ケース。フラグを補完せず帰還 |
| 本番UI | 移動・全図・編成・保存復帰・戦闘後復帰・実際の全滅からの復帰を検査 |

通し検査は初期状態から始め、能力値や解放フラグを注入して勝利させていない。習得した技の装着、現地の休息、獲得した薬を使う。読込境界の392件は意図的な障害注入であり、通常プレイの記録とは別ファイルに保存する。

## 再実行

```powershell
. .\tools\prepare_scope_env.ps1
godot --headless --path . --script res://tools/check_map_graph_definition.gd
godot --headless --path . --script res://tools/check_map_graph_structure.gd
python tools/build_world_terrain.py
python tools/build_world_interiors.py
godot --headless --path . --script res://tools/check_world_terrain.gd
godot --headless --path . --script res://tools/check_world_terrain_boundaries.gd
godot --headless --path . --script res://tools/check_world_terrain_realtime.gd
python tools/check_world_realtime_record.py
godot --headless --path . --script res://tools/check_world_integration.gd
godot --headless --path . --script res://tools/check_world_integration.gd -- --party=3
godot --headless --path . --script res://tools/check_world_state_boundaries.gd
godot --headless --path . --script res://tools/check_world_ui.gd
```

実時間検査は61経路を実際の速度で進むため、約18分を要する。CIでは本番移動処理の再検査と実時間記録の入力ハッシュ照合を行う。地形・グラフ・移動コードが変われば古い実時間記録は失敗になり、再測定が必要になる。

Nativeの実描画はheadlessを外して `check_world_ui.gd` を実行すると `docs/verification/screens/world_*.png` に保存する。UI検査は先に通し検査で作った専用QAセーブを使用する。

## 残る範囲

この接続は約60時間分の内容量達成を証明しない。既存の長編80話案の未制作部分と、人間による完走実測は別の残作業として維持する。新規拠点数、71区画、22戦の件数だけを60時間の代わりにしない。

探索の分かりやすさ、依頼の反復感、報酬の満足度は `PLAYTEST_QUEUE.md` に分離する。これらの未実施を理由に機械作業を停止しない。
