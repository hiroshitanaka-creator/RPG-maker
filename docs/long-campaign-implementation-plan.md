# 60時間向けの内容を接続する設計案

状態: 制作中の設計案。実装済みの内容量や実測時間を示す文書ではない。目標60時間以外の下記の数・構成・名称は設計者の提案であり、依頼者の確定事項と区別する。物語の解答は通常の進捗報告に出さない。

## 維持する条件

Godot 4.7.2-stable / GDScript、3〜4人、既存20職、装着2→3・魔物化+1、町3、ダンジョン5、敵30種を維持する。既存6章案の内部に内容を置き、章・大陸・職業を追加しない。既存25区画、8件の回収、2本の連鎖を削らない。新しい制作phaseや短い版の完成を前提にしない。

## 内容量の設計用仮説

既存の土地に80件のまとまりのある冒険を配置する案を検討する。各冒険は、目的を受け取る場面、複数の観察地点、選べる行動、その行動で変わった結果を持つ。1件を4つの訪問場面と6戦前後で構成し、4件ずつを一つの連作にする。20連作それぞれの4区画を再訪するため、追加80区画・320訪問場面・480戦となる。320枚の新規マップと数えない。これは件数を埋める指示ではない。同じ会話と通路を複製したものは独立した内容として数えない。

| 項目 | 設計予算の仮説 | 測り直すもの |
|---|---|---|
| 戦闘 | 1,200分 | ターン数、人数、コマンド選択、予告を読む時間、再挑戦を分離する。敗北の反復を尺を満たす材料にしない |
| 探索・装置・経路判断 | 800分 | 実際の歩数と、観察・推理・経路選択の時間。待機や移動速度の低下で稼がない |
| 会話・出来事・過去の場面 | 960分 | 読む量と提示順。文章量だけで体験の質や時間を達成扱いにしない |
| 構成の見直し・町での準備 | 640分 | 装着・転職・魔物化の判断と、不要な往復や操作を分ける |
| 合計 | 3,600分 | 全体の初見実測は未実施。上の配分は検証前の仮説 |

現在の3人通し検査では、旧内容の移動1,675マス・戦闘319ターンを観測した。自動操作の経過秒を人間の所要時間へ換算しない。上の予算は、そのまま完成判定や`target_duration_observed`の証拠にしてはならない。実装した内容を棚卸しし、物量と機械的な到達性を確認してから人間の時間確認へ渡す。

## 1件ごとの制作データ

| データ | 必須の内容 |
|---|---|
| IDと時期 | 既存の章・場所・開始条件。前提となる情報を得る前に未来の事情を説明しない |
| 依頼と当事者 | 誰が何を望むか、放置すると何が困るか。作業の手順説明だけにしない |
| 観察 | 目で確認できる状況を複数用意する。目的地のマーカーだけで完結させない |
| 選択 | 少なくとも2つの進め方と、それぞれの結果。単なる名称違いの選択肢にはしない |
| 戦闘 | 敵の役割と編成の意味。既存30種を組み合わせ、HPを増やすだけの長期化にしない |
| 報酬 | 技・役割を選ぶ機会、通路や設備、補給、その土地の変化。必要な消費と一度だけの取得を検査する |
| 設置と回収 | 新たに意味が読み替わる物・台詞にはIDを付け、設置と回収を一組で記録する。既存8件の台帳と混同しない |
| 3人時の文面 | 不在の4人目が話さない。必須情報を4人目だけに持たせない |

人名・新たな出来事・具体的な台詞は提案として作る。魔物化へのNPCの条件分岐は既存3箇所に限定し、新しい依頼人全員へ分岐を増やさない。

## 接続の方針

- 追加内容は独立したデータへ記述し、既存25区画のデータと検査を残す。既存の進行、戦闘、会話、装着、帰還、保存を使って接続する。
- 新規の本編で第1章クリア後の既存イベントを通ったときに、長編の開始フラグを立てる案とする。旧保存に新しい必須内容を割り込ませて、完了した進行を戻さない。直接状態を配置する既存の局所検査と、新規開始からの長編検査を分け、どちらの期待値も削らない。
- 追加内容の完了が必要な本編地点では、該当する進行フラグを確認する。新規開始の通常経路から追加内容をすべて飛ばして結末へ到達できる構造にはしない。
- 情報を見る順序を選べる場所は、前提条件を満たした複数の内容を開く。入力順や再ロードで目的・報酬・回収が二重に進まないようにする。
- 新しい状態は保存対象一覧へ明記する。保存後ロード、帰還再開、全滅後の復帰、旧保存の継続をそれぞれ検査する。
- 技を重ねると反応する敵を使う場合は、予告と対処手段を提示する。同時に複数の高反応敵を置いて、最初の行動前に全滅する構成を作らない。

## 長い経路の検査

実時間の移動や描画を検査する経路と、長い進行を高速に検査する経路を区別する。後者で検査用時計を注入する場合も、通常の移動・衝突・戦闘・会話・保存のAPIを通す。完了フラグの直接設定や戦闘結果の差し替えで到達したことにしない。

検査用時計や自動入力の記録は必ず自動操作として記録し、人間の60時間実測へ混ぜない。保護された第1章スクリプトは変更せず、そのまま実時間で通す。長編の検査予算を増やす場合は、追加した内容量と検査経路に基づいて上限を決め、成功するまで無制限に待つ方法は採らない。

この文書だけでREADY-CONTENT・READY-PATHS・READY-RECORDを完了にしない。次の作業はデータと本番の進行への接続である。
