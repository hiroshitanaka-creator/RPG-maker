# v1の閾値案と暫定検証

2026年9月20日。依頼者の「暫定値を置いて先に進め」に基づく。AC-01の40〜60%、AC-02の10ターン以内80%以上、AC-03の不一致0件、既存の素材規約などは既に指定された条件である。それ以外の数値・測定入力は設計者の**暫定案**であり、依頼者が個別承認した値とは扱わない。業界標準や実測から得た最適値ではなく、この企画の尺・物量・操作方式を根拠に置く初期値である。

## 機械で判定する指標

| T13 物語の提示を省略しない | **既存条件**: 回収8件・連鎖2本、片側欠落・先行回収・未来情報混入・二重報酬が各0件 | 意味の読み替えに必要な情報を全経路に残すため。フラグ成立は理解を証明しない。 | 既存物語監査、二つの再訪順、最悪ケース検査。理解はPT07〜PT11へ分ける。 |
| T14 5〜6時間の尺を実測で確認する | **既存目標**: 有効な初見通し記録で300〜360分、区分不明な放置時間0件 | 依頼者指定の目標を維持。自動操作時間や設計予算330分へ読み替えない。 | 完全な同一版の実測記録をheadlessまたは集計処理で照合。記録未提出はNOT_RUN。人間の操作記録はPLAYTEST_QUEUEへ置き、機械作業を止めない。 |

「既存条件」と記した行にも、検査が全項目を網羅済みという意味はない。検査の追加・拡張が必要な部分は測定方法に記載した。暫定値は今回の指示で測定・準備に使用できるが、凍結契約の書換えや合格後の閾値緩和を許可するものではない。

## 人間が評価する基準案

以下は受入条件へ混ぜず、[PLAYTEST_QUEUE.md](../PLAYTEST_QUEUE.md)に置く。暫定の初期観測単位は初見5人、4人以上を改稿判断の目安にする。原設計の人数案を再利用し、大規模な利用者集団への有効性を証明したとは扱わない。無回答は良い評価へ補完せず、5人未満では判定保留とする。

| 条件文 | 閾値 | その閾値にした理由 | 測定方法 |
|---|---|---|---|
| PT01 職業・装着・魔物化の選択が面白い | **暫定**: 3要素を別々に5段階で評価し、各要素で5人中4人以上が4以上 | 企画の背骨3点を合算平均で相殺しない。5は面白い、1は面白くないとする。 | 序盤と完走後に評点と具体的な選択理由を聞く。操作回数を面白さへ変換しない。 |
| PT02 戦闘難易度が適切と感じられる | **暫定**: 5人中4人以上が3または4 | 既存の難易度尺度は1＝易しい、5＝難しい。満足度と異なり5を最良と扱わず、考える余地がある3〜4を初期目標とする。 | 全滅・帰還・構成変更の理由と評点を併記。主観の適切さを勝率だけで認定しない。 |
| PT03 探索の目的と行き先が分かる | **暫定**: 分かりやすさ4以上が5人中4人以上。同じ必須地点で同じ理由により2人以上が停止したら修正対象 | 初回の小規模観測でも、同じ案内不足を2人が経験すれば偶発として扱わない。 | 誘導なしの観察と本人の理由。短い寄り道や任意探索を迷走として自動減点しない。 |
| PT04 報酬を得る価値を感じる | **暫定**: 満足度4以上が5人中4人以上 | 実際の薬付与と満足は別であり、薬の個数を増やすだけで合格にしない。 | 欲しかった物・使った場面・報酬のために寄り道した理由を聞く。 |
| PT05 進行のテンポを保てる | **暫定**: テンポ評価4以上が5人中4人以上。同じ反復箇所を2人以上が退屈と挙げたら修正対象 | 25区画で5種類の通路配置を共有するため、反復が集中する箇所を平均プレイ時間で見落とさない。 | 5＝進みやすい、1＝間延びすると定義して、戦闘・移動・説明のどこかを特定する。 |
| PT06 動作・外見が自然で、表示を読める | **暫定**: 自然さ・読みやすさを別々に評価し、各項目で5人中4人以上が4以上 | 接地や矩形が一致しても、人物の同一性・歩行位相・文章の読みやすさは保証できない。 | 最終サイズの実画面で移動・攻撃・被弾・変身を見て、違和感のある人物・コマ・画面を記録する。 |
| PT07 既知の結果を踏まえて過去を見る | **原設計を使う暫定値**: 5人中4人以上 | 現在の姿は既知、選択の理由は未解決、という二つを同時に捉えられたかを確認する。 | 第2章末の自由回答を人間が照合する。 |
| PT08 同じ証拠の意味を読み替える | **原設計を使う暫定値**: 5人中4人以上 | R07の観測事実を保ったまま原因と根拠を更新できることが核である。 | 回収前後の回答で、板の傷という事実・練習という原因・根拠場面を確認する。 |
| PT09 再訪を初回の場面と結び付ける | **原設計を使う暫定値**: 5人中4人以上 | 同じ地点へ歩けるだけでなく、初回との関係を受け取れる必要がある。 | 第5章で本人に理由を説明してもらう。立ち止まりだけでは理解扱いにしない。 |
| PT10 回収直後に次の疑問を持つ | **原設計を使う暫定値**: R01・R04それぞれ5人中4人以上 | 2本の連鎖のどちらか片方だけ成功しても相殺しない。 | 「分かったこと／次に確かめたいこと」の自由回答を照合する。 |
| PT11 制約と人物の選択を結び付ける | **原設計を使う暫定値**: 5人中4人以上 | 番人が残した技、習得の持ち越し、魔物化と分担を関係付けられることを確認する。 | 現行の通常2→3枠・魔物化+1を前提に、番人が合図技を残した理由を聞く。 |
| PT12 中断後に手帳から再開できる | **暫定**: 5人中4人以上が60秒以内に目的・証拠へ到達し、次の行動を説明できる | 原設計の60秒を初期目安として採用。速く画面を開けることと、進行を理解したことを分けて観測する。 | 操作ログの時刻差は機械集計、説明の意味は人間が評価する。 |
| PT14 噂と図鑑から上級職を推測できる | **暫定**: 5人中4人以上が少なくとも1職の条件と根拠を説明できる | 解放条件を一覧で隠す仕様が、単なる情報不足になっていないかを初期観測するため。全4職の発見を必須にして任意探索を強制しない。 | 本人の推測と参照した記述を照合する。 |
| PT15 侵蝕の代償を知って選べる | **暫定**: 5人中4人以上が90到達前に不可逆性を説明できる | 戻れない境界を越える操作の確認だけでは、結果の理解を保証できないため。 | 予想する結果を本人に尋ねる。踏み越えること自体は要求しない。 |

物語の途中質問はその後の注意を変えるため、尺測定の試行には挟まない。物語の観測は別の初見試行で行う。人数は研究上の検出力に基づく保証ではなく、v1で修正箇所を拾う暫定の観測規模である。

## 暫定の固定戦闘入力

`data/acceptance_battle_profile_v1.json`を測定前に保存した。対象は`gate_beast`、`elder_slime`、`night_bat`、`ancient_shell`、`core_wisp`、`flood_beast`。全通常戦闘や全編完走率への適用を確定したものではない。

- 4人は戦士・武闘家・僧侶・魔法使い。3人は先頭3人。各人は初期職だけを1回マスターし、その職の2技を定義順で装着する。全員人間、侵蝕0、通常2枠、HP・MP満タン、薬3個。技・能力値は現在の実ゲーム定義を使い、各ケースの全初期状態を結果へ保存する。
- 行動方針は、使用可能な蘇生、HP50%未満の仲間への回復、HP25%未満への薬、先頭の生存敵へ最大の予測ダメージとなる攻撃の順。HP比率が同じなら人物ID順、同ダメージなら通常攻撃／装着順を優先する。将来の乱数結果は参照しない。人間の初見判断を模擬したとは扱わない。
- 1ターンは生存者のコマンドをまとめて解決する1回。毎試行で同じ初期状態へ戻し、シード以外の入力を変えない。上限は暫定30ターン。敵の能力値・技・AIを測定に合わせて変更していない。

初回の有効な測定は12,000試行、実行エラー0。AC-01は全12ケースで目標外、勝率98〜100%。AC-02は11,975／12,000＝99.7917%で範囲内。打切り0件。閾値または初期HPを変更してこの結果を合格へ変換しない。[生の試行記録](verification/provisional-battle-acceptance.json)を保持する。これは暫定入力での判定であり、正式凍結した戦闘バランス全体の受入結果ではない。

最初の起動で発生した検証入力のJSON数値型の比較不備とログ書込環境のエラーは修正して再実行した。その起動は有効な戦闘測定や実装前FAIL証拠には数えていない。

## 保存検査で見つけた不備と対応

初版の保存検査はコピーの準備に`restore`を使っていたため、比較前に型を変える可能性があり、受入証拠には採用しなかった。実際の保存元から直接採取する検査へ変更すると、装着技と戦闘履歴の配列要素型がロード後に失われる不備を検出した。比較器の判定は緩めていない。

`SavedValueTypes`と保存処理で、JSONが保持できない型を`_saved_value_types`へ記録し、読込時に復元するよう修正した。整数と、整数値を持つ小数も区別する。補助情報が不正なら現在の状態を変更せず拒否し、補助情報がない従来保存は既存の読込方式で扱う。試遊全体の履歴を進行セーブ時点へ巻き戻す変更はしていない。

追加の数値境界検査では`1.0 / 3.0`が既定精度のJSON出力で変わることも検出した。進行セーブと共通のJSON書出しをGodotの完全精度指定へ変更し、割り切れない小数と小さい小数を含む値の一致を検査する。

修正後は3人・4人の通常進行と8種の魔物化等を含めて各357状態、計714状態の直接比較で不一致0件。比較器の7種の改変検出、型付き配列・整数と小数・旧形式・壊れた補助情報の検査も実行した。最終記録の検査コードSHAと作業中のファイルが一致することを確認し、途中版の結果と区別した。CIには既存の全章検査を継承した保存検査と、型の境界検査を接続した。未達のAC-01をCIの成功へ混ぜない。
