# 新しい水際素材の検査案

**不採用・未適用。** 色画像と透明範囲の画像を別々の不透明画像として保存し、描画時に合成する方式で解決した。Godotで合成した結果は、従来の透明な画像と全画素一致を確認した。検査本体の改訂は不要になり、承認質問を取り下げた。以下と隣のpatchは検討記録として残す。

対象は `tools/validate_assets.py` と、新規の `assets/tiles/world_connected_water.png` の登録だけ。既存の素材・歩行・戦闘・47接続タイルの判定、R-01〜R-08、保護ファイルには変更を加えない。

現在の検査は `frame` と `grid` を持つすべての画像に、接地行の一致と空コマ禁止を適用する。水際の透明な重ね描きでは、上半分に水があるコマや、水がないコマも正しいため、この条件とは両立しない。台帳からframe/gridを外して検査を避けることはしない。

提案する変更：新しい種類 `terrain_water_overlay` を導入し、上記の新規ファイルだけに適用する。寸法・32pxの区切り・色数64以内・パレット所属・二値透過・出所の検査は従来どおり。接地行と空コマの代わりに、512種類×16模様位置の全コマの透過輪郭が、周囲9セルから求める正しい輪郭と1画素も違わないことを検査する。空コマも、計算上水がない場合だけ許可する。種類とファイルパスを両方限定し、人物などをこの種類へ付け替えて検査を逃れることは認めない。

判定は生成側のNumPy処理と独立した整数計算を使い、CIに追加のライブラリは要求しない。画像の破損を1画素入れたときに不合格になる確認も追加する。変更はGitで元に戻せる。

代案：透明な重ね描きをやめ、草地・森・山など背景ごとに不透明な水際素材を用意する。この場合は検査を変えずに進められるが、素材数と描画用のメモリが増え、地面との合成も背景別に管理する必要がある。
