# スプリント2とR-07のメニュー入力の衝突

状態：提案のみ。保護された検査と文書は変更していない。

体験仕様は探索中の常設ボタン列をなくし、メニューキーでコマンド窓を開く。一方、凍結済みR-07は探索中の可視「セーブ」と「メニュー」を直接クリックする。ボタンを窓の中へ移すだけでは、窓を開く前に検査が失敗する。透明なボタンや検査専用分岐で回避しない。

- `tools/smoke_first_region.gd:197`：キーの許可一覧にEscapeがない。
- 同`:499`：メニューを開かず「セーブ」をクリックする。
- 同`:502`、同`:612`：探索中の「メニュー」をクリックする。
- `docs/first-region-acceptance.md`：通常UIのラベルとA14の入力制限も同期が必要。

## 推奨案

依頼者が添付パッチの通常入力の変更を確認し、保護対象2ファイルと `.scope-lock/frozen-files.json` の対応ハッシュを更新する。R-01〜R-08のverify、A01〜A14の条件・個数・観測・上限は変えない。追加するキーは、一般プレイヤーも使うEscapeのみ。

変更後の保存確認は、Escape→セーブ→現在の冒険に戻る→実移動→Escape→手動セーブから再開。位置・向き・所持品・パーティの一致判定は元のまま。

具体的な差分は `sprint2-r07-menu-input.patch`。Gitの履歴から元に戻せる。まだ適用していない。

## 代替案

依頼者が今回は仕様の例外として画面上のセーブ・メニューボタンを残すと決める。この場合は検査の変更は不要だが、今回望まれた画面構成とは異なる。

この判断が必要なのは探索中のメニュー入力だけ。原画の保管、歩行素材、地形表示、会話窓、戦闘背景、音、配置案の準備は独立して進められる。
