# 正式目標60時間への変更

2026年9月20日、依頼者は「60時間を正式目標に戻す」と明示回答した。現在の制作目標は約60時間であり、5〜6時間の完成を経由する条件は設けない。既存コード・素材・物語は現在の資産として保持する。

## 完成判定と現在地

- 正式な目標値は3,600分。測定・集計の判定幅は暫定で3,240〜3,960分（54〜66時間、±10%）。幅の最終承認を待って実装・検証を止めない。
- 現在の25区画・70戦・旧330分の設計予算は、60時間分の内容が存在する証拠ではない。現状の内容を10倍に水増ししたり、移動や戦闘を遅くしたりして達成扱いにしない。
- 60時間分の探索・戦闘・職業選択・物語の内容と、初見の実測は未達として保持する。機械検査の成功、合成した時計、無操作放置は実測の代わりにしない。
- 目標尺以外の固定条件・非目標は維持する。R-01〜R-08のdone_when・verifyと保護テストは変更しない。今回の明示的な目標変更を`.scope-lock/spec.lock.json`の改訂履歴に残した。

## 初見体験を温存する扱い

- 依頼者本人を開発中の繰返し試遊の担当にしない。機械で検出できる不具合、進行不能、保存破損、操作の欠落を開発側で確認する。
- 通常の報告には、物語の答え・結末・未体験の展開を含めない。技術的な結果と残作業を先に示す。
- 人間の主観評価が必要な場合は`PLAYTEST_QUEUE.md`へ分離する。第三者の初見試遊を利用できる場合はその記録を使い、依頼者本人の試遊を必須の作業依頼にしない。外部の人へ無断で依頼・送信は行わない。
- 60時間という目標を、能力や意欲を評価する言葉で退けない。実装済み・未実装・未測定を具体的に示して進める。

## 変更した計測

`data/duration_target_v1.json`を目標値の定義元とする。ゲームの試遊レポートとPython集計の両方でこの定義を参照し、目標版IDが一致しない旧記録は受入候補にしない。保存された進行と試遊履歴は保持する。

`tools/check_duration_target.gd`は、旧330分の拒否、暫定幅の両端、目標版不明、自動操作の除外を検査する。この検査の時計は合成入力であり、60時間を遊んだ記録ではない。
